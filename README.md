## Стек

- Ruby on Rails 8, `inertia_rails`, Vite
- Svelte 5 (runes) + TypeScript, shadcn-svelte, Tailwind CSS
- EventCalendar (`@event-calendar/core`) — сетка переговорных; иконки — Phosphor (`phosphor-svelte`)
- PostgreSQL 17 (локально — контейнер из `compose.yml`, в проде — accessory Kamal)
- Solid Queue для фоновых задач, Solid Cache для кеша
- Встроенная аутентификация Rails 8
- Kamal для деплоя
- Minitest

## Как запустить

Нужны Ruby (версия в `.ruby-version`), Node 20+ и Docker (только ради Postgres).

```bash
docker compose up -d db   # PostgreSQL на localhost:5432, логин/пароль postgres/postgres
bin/setup --skip-server   # гемы, npm-пакеты, база, миграции
bin/rails db:seed         # демо-офис: 60 человек, 40 мест, 6 переговорных
bin/dev                   # Rails на :3000 и Vite на :3036
```

## Демонстрация авто-освобождения

Сиды создают бронь переговорной, которая началась больше десяти минут назад и не
была подтверждена. Задача освобождает её:

```bash
bin/rails office:release
```

После этого слот на экране «Переговорные» снова свободен и помечен как
освободившийся автоматически.

Сиды ставят эту бронь относительно текущего момента, поэтому **перед показом их
стоит прогнать заново**: `bin/rails db:seed`. Если прогнать их в первый час
работы офиса, подходящих начавшихся слотов ещё нет — сиды возьмут первые слоты
дня и напечатают, во сколько брошенную бронь можно будет освободить.

В разработке фоновые задачи по расписанию не крутятся — очередь Solid Queue
настроена только в проде, — поэтому задача запускается вручную. В проде
`ReleaseAbandonedBookingsJob` работает раз в минуту, а
`ExpandRecurringSchedulesJob` — раз в сутки; расписание в `config/recurring.yml`.

## Тесты

```bash
bin/rails test
```

Модельные тесты покрывают то, что нельзя сломать незаметно: двойная бронь слота
отсекается базой, авто-освобождение снимает неподтверждённую бронь целиком, не
трогает встречу с чек-ином, а повторяющееся расписание разворачивается в нужные
дни недели. Ещё по одному запросу на каждый из трёх экранов — они проверяют, что
страница собирается с реальными данными: это самая дешёвая защита от пропа,
переименованного с одной стороны.

## Схема данных

| Таблица | Что хранит |
| --- | --- |
| `zones` | области офиса: название, этаж |
| `teams` | команда и её «домашняя» зона |
| `users` | сотрудник, команда, избранное место |
| `resources` | место или переговорная: `kind`, зона, вместимость, координаты на карте |
| `bookings` | бронь: ресурс, человек, начало, конец, `group_id`, состояние, время чек-ина |
| `recurring_schedules` | дни недели, в которые человек обычно приезжает, и его место |

Одна бронь — один слот. У переговорной слот длится 30 минут, у рабочего места —
весь день и начинается в полночь. Встреча длиннее получаса — это несколько строк
с общим `group_id`.

Три индекса держат все инварианты:

```sql
UNIQUE (resource_id, starts_at) WHERE state IN ('booked','checked_in')
UNIQUE (user_id, starts_at)     WHERE state IN ('booked','checked_in')
UNIQUE (grid_row, grid_col)     WHERE kind = 'desk'
```

Первый запрещает двойную бронь ресурса, второй — находиться в двух местах
одновременно (для мест это же означает «одно место на человека в день»), третий
не даёт поставить два стола в одну клетку карты. Индексы частичные: освобождённая
бронь остаётся в истории, но слот не занимает.

Почему решения приняты именно такие — в `DECISIONS.md`. Что входит в MVP и что
сознательно не входит — в `SCOPE.md`.

## Деплой

Kamal, один контейнер на любом VPS. Перед первым деплоем в `config/deploy.yml`
нужно указать свои значения:

- `servers.web` — адрес сервера (доступ по SSH под root, по ключу);
- `proxy.host` — домен, на который выпускается сертификат Let's Encrypt. Пока
  домена нет, подходит `<ip-через-дефисы>.sslip.io` — имя, которое всегда
  указывает на этот IP;
- `registry` оставлен `localhost:5555` — это локальный реестр Kamal: образ
  собирается и хранится на машине, откуда идёт деплой, а сервер забирает его
  через SSH-соединение. Никакого Docker Hub не нужно.

HTTPS настраивается в двух файлах сразу, и они должны быть согласованы:
`proxy.ssl` в `config/deploy.yml` терминирует TLS, а `config.assume_ssl` и
`config.force_ssl` в `config/environments/production.rb` заставляют приложение
доверять прокси и отдавать cookie с флагом `secure`. Если разворачиваете без
домена, выключать нужно обе половины.

```bash
bin/kamal setup     # первый деплой: ставит Docker на сервер, поднимает реестр, Postgres и приложение
bin/kamal deploy    # последующие
bin/kamal seed      # пересобрать демо-офис на сервере (перед показом)
bin/kamal release   # запустить авто-освобождение руками (во время показа)
bin/kamal logs      # хвост логов приложения
```

Сейчас приложение развёрнуто на `https://201-24-48-232.sslip.io`.

На самом сервере руками сделано одно: SSH только по ключу
(`/etc/ssh/sshd_config.d/10-keys-only.conf` — `PasswordAuthentication no`,
`PermitRootLogin prohibit-password`) и машина, с которой идёт деплой, внесена в
`PerSourcePenaltyExemptList`: новый OpenSSH штрафует источник за всплески
соединений, а Kamal открывает их несколько сразу — без исключения деплой ловил
таймауты. Всё остальное на сервере ставит и настраивает `kamal setup`.

Postgres поднимается рядом с приложением как accessory Kamal (`accessories.db`
в `config/deploy.yml`) и хранит данные в каталоге на сервере. Пароль лежит в
файле `.kamal/postgres_password` на машине, откуда идёт деплой (файл в
`.gitignore`, как и `config/master.key`; создать: `openssl rand -hex 24 >
.kamal/postgres_password`) — `.kamal/secrets` пробрасывает его и в контейнер
базы, и в приложение. Все три
базы Rails 8 (основная, кеш, очередь) живут в одном сервере Postgres;
`db:prepare` в `bin/docker-entrypoint` создаёт их при первом запуске.

Фоновые задачи выполняются внутри процесса Puma — за это отвечает
`SOLID_QUEUE_IN_PUMA: true`; отдельная машина под задачи при такой нагрузке не
нужна.
