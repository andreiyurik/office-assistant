# Перевод интерфейса на Carbon Design System

Как интерфейс переехал на Carbon и сколько это стоило. Замеры сделаны на ветке
`spike/carbon`, которая затем взята в основную; состояние до перехода помечено
тегом `shadcn-baseline`.

Продукт, бэкенд и связка Rails + Inertia + Svelte 5 не менялись. Заменён целиком
слой дизайн-системы: вместо shadcn-svelte + Tailwind + Phosphor —
`carbon-components-svelte` 0.111, `carbon-icons-svelte` и IBM Plex Sans.

Условие было одно: не «покрасить под Carbon», а взять его сетку, токены,
типографику, компоненты и паттерны. Поэтому старая система удалена целиком, а
не оставлена под низом — смесь двух систем дороже любой из них по отдельности.

## Что изменилось

| Слой | Что стало |
| --- | --- |
| Модели, миграции, индексы, задачи, сиды | **не изменилось ни на строку** |
| Контроллеры | **не изменилось ни на строку** — пропсы те же |
| Вьюха Rails | одна строка: `<html theme="g10">` |
| Оболочка | `AppLayout` → `Header` + `HeaderNav` + `HeaderAction` + `SideNav` + `Content` |
| «Кто в офисе» | список `<li>` → `DataTable` с `Toolbar`/`ToolbarSearch`, `Tag`, `Tile` |
| «Карта мест» | зоны → `Tile`, места → `SelectableTile`, дни недели → `Toggle`, перенос брони → `Modal` |
| «Переговорные» | сайдбар → `Tile`, действия по встрече → `Modal`, календарь перекрашен на `--cds-*` |
| Логин | свои поля → `TextInput`, `PasswordInput`, `InlineNotification` |
| Ошибки | своя плашка → `ToastNotification` |
| Стили | 137 строк токенов Tailwind → 18 строк импортов Carbon и одно правило для `body` |
| Раскладка | утилиты Tailwind → CSS Grid/Flex на переменных `--cds-spacing-*` |

Замер: `git diff --numstat shadcn-baseline..main` — тег помечает состояние до
перехода.

| Область | Строк |
| --- | --- |
| страницы (`pages/`) | +1066 / −427 |
| общие компоненты (`lib/`) | +341 / −349 |
| стили и точка входа | +18 / −135 |
| конфиг сборки и зависимости | +8 / −34 |
| сборка образа и CI | +19 / −3 |
| сервер (вьюха) | +4 / −1 |
| **всего без lock-файла** | **+1468 / −949** |
| `package-lock.json` | +44 / −769 |

Строк стало больше на 519. Почти весь прирост — в `pages/`: разметка ужалась, но
раскладка переехала из классов в блоки `<style>`, и это честная цена отказа от
утилитарного CSS. Зато `-769` строк в lock-файле: девять пакетов ушли, три
пришли.

## Что оказалось лучше

- **Токены вместо палитры.** Раньше цвета жили в `application.css` как
  `oklch(...)` и дублировались в календаре, на карте мест и в легендах. Сейчас в
  проекте нет ни одного значения цвета: всё — `--cds-*`. Календарь
  `@event-calendar` перестал быть чужим блоком именно из-за этого: его `--ec-*`
  указывают на те же токены, что и остальной экран.
- **Доступность приходит с компонентом.** Это единственное, за что Carbon стоит
  своей цены. `DataTable` даёт сортировку с клавиатуры и корректную семантику
  таблицы; `ContentSwitcher` — роль `tablist` и roving tabindex; `Modal` —
  ловушку фокуса, Esc, закрытие по клику вне и возврат фокуса; `SelectableTile` —
  настоящий чекбокс под плиткой. Проверено в браузере: стрелки в полосе дней
  двигают фокус, не открывая день; Enter открывает; Tab доходит до действия в
  строке таблицы за 21 остановку.
- **Состояния перестали быть ручной работой.** Hover, focus, disabled, selected
  у мест и кнопок больше не описываются в проекте. На карте мест это заметнее
  всего: было пять веток в `deskClasses()` со списками классов, стало
  `selected` + `disabled` и три правила фона.
- **Экран логина, поиск в таблице и подтверждение переноса стоили почти
  ничего.** `ToolbarSearch shouldFilterRows` — один атрибут вместо фильтрации
  руками; `PasswordInput` принёс кнопку «показать пароль», которой не было.
- **Сборка стала проще.** Из `vite.config.ts` ушёл плагин, из проекта —
  `components.json`, `lib/utils.ts` и связка `clsx` + `tailwind-merge` +
  `tailwind-variants`.

## Чем платим

### Вес

Замер: `bin/vite build` на каждой ветке, gzip -9 по всем файлам.

| | `shadcn-baseline` | Carbon | Разница |
| --- | --- | --- | --- |
| JS, gzip | 116.7 кБ | 133.5 кБ | +16.8 кБ (+14%) |
| CSS, gzip | 11.6 кБ | 88.3 кБ | **+76.7 кБ (в 7.6 раза)** |
| CSS, без сжатия | 61.5 кБ | 905.3 кБ | +844 кБ |
| Шрифт, реально скачивается | ≈67 кБ | 82.5 кБ | +15.5 кБ |
| **Первая загрузка, gzip** | **≈195 кБ** | **≈304 кБ** | **+109 кБ** |

CSS — главная статья. `carbon-components-svelte` отдаёт один скомпилированный
файл со стилями **всех** компонентов, а не только использованных: tree-shaking
для него не работает, потому что это не модули, а один `.css`. Мы используем
около двадцати компонентов из сотни с лишним и платим за все.

Из двух вариантов взят `all.css` (88.3 кБ gzip), а не `g10.css` (70.2 кБ):
одна тема на 18 кБ дешевле, но она компилирует палитру в литеральные hex и не
публикует `--cds-*`. Тогда календарь и карта мест держали бы собственные копии
тех же цветов — второй набор токенов, то есть ровно то, ради чего всё
затевалось. 18 кБ за один источник цвета — размен в пользу токенов.

Шрифт: подключены два начертания (400 и 600) в виде split-файлов с
`unicode-range`, поэтому русская страница тянет четыре файла из двенадцати
собранных. Начертание 300 сначала подключил и убрал: ни один стиль Carbon,
который здесь используется, его не просит.

### Зависимости и телеметрия

Ушло девять пакетов, пришло три: `carbon-components-svelte`,
`carbon-icons-svelte`, `@ibm/plex-sans`.

`carbon-components-svelte` тянет `@ibm/telemetry-js` и запускает его из
`postinstall`. Отключено в `package.json` через `allowScripts` (npm 11 сам
блокирует install-скрипты, здесь это зафиксировано явно) плюс
`IBM_TELEMETRY_DISABLED=true` в CI, `Dockerfile` и `bin/setup` — на случай npm,
который поля не знает. Мелочь, но её нужно знать заранее: без этого каждая
установка зависимостей уходит наружу.

Вместо `@ibm/plex` из задания взят `@ibm/plex-sans`: тот же шрифт от IBM, 4 МБ
против 186 МБ распакованных. Монолитный пакет везёт Serif, Mono, Condensed и
все форматы, из которых используется два файла.

### Svelte 5

Библиотека написана на Svelte 4 и работает в режиме совместимости. Это скорее
сработало, чем нет, но три вещи стоили времени, и все три нашлись только тогда,
когда экраны стали кликать браузером, а не смотреть глазами:

1. **`Modal` не забирал фокус.** Плитка места — это `<label>` над чекбоксом, и
   браузер отдаёт фокус чекбоксу *после* обработчика клика, поверх фокуса,
   который модалка только что забрала. Esc в результате было некому слушать.
   Лечится `preventDefault()` на ветке переноса.
2. **`SelectableTile` держит своё состояние.** Клик переключает галочку сам, и
   отменённый перенос оставлял отметку на месте, которое никто не занял.
   Пришлось сделать плитку управляемой: `bind:selected` плюс пересинхронизация
   из пропсов после каждого ответа сервера.
3. **Типы `DataTable` строгие до `as const`.** Обычный массив заголовков не
   проходит проверку: ключ колонки типизирован как литеральный ключ строки.

Что при этом **не** сломалось и чего я ожидал: директивы `on:` на компонентах
Carbon работают из компонента на рунах (`on:click:row`, `on:toggle`,
`on:close`), слоты принимаются как сниппеты, `bind:` работает в обе стороны.
Это снимало главный риск затеи.

### Интерфейс

- **`DataTable` не умеет группировать строки.** Заголовки «Ваша команда» и
  «Остальные» на экране «Кто в офисе» пришлось заменить сортировкой и тегом на
  строке. Информация та же, но взгляд больше не цепляется за границу групп.
- **На телефоне таблица не помещается.** Четыре колонки шире 390 px, и за экран
  уезжала именно та, где действие. Ниже breakpoint `md` колонка «Команда»
  убирается (она и так фильтр над таблицей), а кнопка «Сесть рядом» становится
  иконкой. Это `breakpointObserver` самого Carbon, но это всё равно логика,
  которой раньше не было.
- **Плитка Carbon — это карточка 8×4 rem.** Место на плане этажа — квадрат
  размером с палец. Габариты пришлось задать самому; всё остальное поведение
  плитки осталось.
- **Плитка на плитке невидима.** `SelectableTile` по умолчанию `ui-01` — тот же
  белый, что у зоны под ней. Без `light` свободные места не имели рамки вовсе.
  Слоевая модель Carbon требует внимания: то же самое всплыло на логине, где
  белое поле стояло на белой панели.
- **Отключённая плитка на Carbon даёт контраст 1.3:1.** Самая дорогая находка, и
  она обидная: библиотеку берут ради доступности, а карта мест из коробки её
  провалила. Причина не в баге, а в столкновении назначений — `disabled` красит
  содержимое в `disabled-02`, и это правильный цвет для подписи выключённой
  кнопки. Но здесь та же плитка несёт данные: кто сидит за столом. Пришлось
  вернуть тексту `text-02` (5.9:1) и объяснить это в коде.
- **Наведение на свободное место делало его серее занятого.** `hover-ui`
  (`#e5e5e5`) темнее, чем `ui-03` (`#e0e0e0`), которым помечено «занято». На
  экране, где всё решается цветом заливки, палитра Carbon кончается быстрее, чем
  состояния: наведение пришлось увести с заливки на рамку.
- **Полоса дней шире телефона.** Пять `Switch` в `ContentSwitcher` не влезают в
  390 px и скроллятся вбок. Раньше пять компактных плиток помещались.
- **`Modal` не портальный.** В 0.111 он рендерится на месте и держится на
  `position: fixed`; в вёрстке проекта это работает, но контейнер с `transform`
  выше по дереву его сломает.

### Что пришлось делать не по-карбоновски

- **Плана этажа в Carbon нет** — как нет его в Bootstrap и Mantine (см.
  `SPIKE.md`). Сетка зоны — свой CSS Grid в любом стеке.
- **Полоса чек-ина** сделана `InlineNotification` в шапке контента, а не
  `HeaderGlobalAction`, как предполагало задание. `HeaderGlobalAction` — иконка
  без подписи, а вся механика продукта держится на фразе «подтвердите, иначе
  бронь снимется через N минут». Иконка эту фразу убивает.
- **Имя пользователя и выход** — `HeaderAction` с панелью, а не отдельный
  `HeaderGlobalAction` на выход: один компонент вместо двух, и это штатный
  паттерн аккаунта в IBM-продуктах.

## Что осталось непроверенным

Протягивание в календаре: колбэк `select` срабатывает, но синтетический
указатель Playwright всегда отдаёт диапазон в один слот, поэтому бронь на
полтора часа перетаскиванием headless-браузером подтвердить не удалось. Код
выделения побайтово совпадает с состоянием до перехода — это ограничение
стенда, а не регрессия. Клик, чек-ин, отмена, обе модалки, тост и вся навигация проверены
браузером; ошибок в консоли нет ни на одном экране.

## Вывод для защиты

Carbon переводит интерфейс из «сделано аккуратно» в «сделано по системе»: цвет
перестаёт быть решением, состояния компонентов перестают быть кодом, а
доступность приходит по умолчанию, а не пишется на каждом экране заново. За это
заплачено **+109 кБ gzip на первую загрузку, из которых 77 кБ — CSS компонентов,
которые продукт не использует**, режимом совместимости со Svelte 4 и 519
строками кода.

Размен принят: это внутренний сервис, который открывают ежедневно и с офисной
сети, поэтому вес первой загрузки здесь стоит дешевле, чем язык интерфейса,
который не переизобретается на каждом новом экране. Оговорка, которую видно
только после переноса: **доступность Carbon не автоматическая**. Дизайн-ревью
нашло на карте мест контраст 1.3:1 — библиотека красит отключённую плитку в
цвет для подписи неактивной кнопки, а та же плитка несёт данные о том, кто за
столом сидит. Система задаёт язык и снимает рутину, но не отменяет дизайнера:
она отвечает за компоненты, а не за то, что мы ими говорим.

Условие, при котором решение стоит пересмотреть, узкое и техническое: если 77 кБ
неиспользуемого CSS станут заметны на метрике загрузки, у Carbon v11
(`@carbon/styles`) стили собираются из модулей и tree-shaking работает — это
переезд на другой пакет той же системы, а не отказ от неё.

## Как воспроизвести замеры

Запуск приложения — в `README.md`. Состояние до перехода помечено тегом, так что
обе половины сравнения доступны:

```bash
git diff --numstat shadcn-baseline..main    # объём изменений по областям
git switch --detach shadcn-baseline         # версия на shadcn
npm ci && bin/vite build                    # состав зависимостей там другой
git switch main
npm ci && bin/vite build
```

Вес считался по `public/vite-dev/assets` с `gzip -9`, отдельно по `js`, `css` и
`woff2`; шрифты — по тем файлам, которые браузер действительно запрашивает, а не
по всем собранным.
